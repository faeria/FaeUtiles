# Cortex — capacités des API WoW Retail 12.x / Midnight

Audit arrêté au **20 août 2026** sur WoW Retail **12.1.0**, interface **120100**, build **12.1.0.69382**. Source de vérité : branche `live` de `Gethe/wow-ui-source`, commit [`9f2b839dbb9059f00dedb10628db1da28dd9cad4`](https://github.com/Gethe/wow-ui-source/tree/9f2b839dbb9059f00dedb10628db1da28dd9cad4).

Ce document décrit ce qu'un addon Lua chargé dans le client peut lire. Il ne couvre pas les API web Battle.net, ni une base de données externe. Les restrictions pouvant changer dans une prochaine version 12.x, l'audit doit être rejoué à chaque changement de `## Interface`.

## Légende

- **AVAILABLE** : données publiques et suffisamment complètes pour l'usage indiqué.
- **PARTIAL** : données présentes, mais limitées par le personnage actif, un cache, une interaction UI, une liste d'identifiants connue, ou une absence d'historique complet.
- **RESTRICTED** : API ou valeurs conditionnées par les restrictions Midnight, le combat, une carte/instance, la messagerie, une interaction utilisateur ou une action protégée.
- **UNAVAILABLE** : aucune API client vérifiée ne fournit cette donnée avec la portée demandée.
- **TO VERIFY** : contrat non établi par les définitions générées du build audité. Cortex ne doit pas l'utiliser avant vérification sur un build Retail correspondant.

`AllowedWhenUntainted` ne veut pas dire « toujours disponible ». Cela signifie que l'argument secret n'est accepté que depuis un contexte non contaminé. Une fonction peut en plus produire une valeur secrète selon son annotation `SecretWhen*`.

## Changements Midnight à intégrer dans l'architecture

### Secret Values

Les secrets ne sont pas seulement une restriction de combat. Le build audité documente notamment :

- `SecretWhenInCombat` : restrictions de combat actives;
- `SecretWhenUnitIdentityRestricted` : unité non contrôlée et hors groupe/raid, avec propagation dans les jetons composés;
- `SecretOnRestrictedMaps` : carte telle qu'un donjon ou un raid;
- `SecretInChatMessagingLockdown` : rencontre, challenge mode, PvP ou carte à communication restreinte;
- des familles spécialisées pour auras, cooldowns, casts, puissances, statistiques, menace et santé.

Cortex doit considérer chaque annotation comme faisant partie du contrat de l'API. Avant de comparer, formater, indexer ou persister une valeur potentiellement secrète, utiliser les primitives vérifiées `issecretvalue`, `issecrettable`, `canaccessvalue` et `canaccesstable`. Si l'accès est impossible, abandonner la donnée; ne pas tenter de la convertir ou de la transmettre.

### Restrictions d'addon

`Enum.AddOnRestrictionType` contient six états indépendants : `Combat`, `Encounter`, `ChallengeMode`, `PvPMatch`, `Map` et `Chat`. Les APIs de contrôle vérifiées sont :

- `C_RestrictedActions.GetAddOnRestrictionState(type)`;
- `C_RestrictedActions.IsAddOnRestrictionActive(type)`;
- `ADDON_RESTRICTION_STATE_CHANGED`;
- `InCombatLockdown()` pour le lockdown historique des actions/cadres protégés.

`InCombatLockdown()` ne remplace donc pas les six états Midnight. Un collecteur Cortex sûr doit se désactiver sur les états pertinents et attendre leur désactivation avant de reconstruire son snapshot.

### Combat, instances et journal de combat

`COMBAT_LOG_EVENT` et `COMBAT_LOG_EVENT_UNFILTERED` sont explicitement marqués `HasRestrictions = true`. `C_CombatLog.IsCombatLogRestricted()` est le garde minimum, mais ne transforme pas le flux en source exhaustive. `C_CombatLogSecure` est lui aussi restreint. Le MVP ne doit pas dépendre du combat log brut.

Le chemin fiable pour un bilan est `C_DamageMeter`, après combat seulement : ses récupérations de session sont `SecretWhenInCombat`. Il faut aussi tester `C_DamageMeter.IsDamageMeterAvailable()` car le système peut être indisponible et fournit alors une raison.

Une instance n'interdit pas uniformément toutes les lectures. Elle peut activer une ou plusieurs restrictions `Encounter`, `ChallengeMode`, `Map` et `Chat`; seules les annotations de chaque API permettent de conclure. Cortex ne doit pas extrapoler une autorisation d'une API à une autre.

### Actions protégées et combat lockdown

Cortex doit rester un conseiller en lecture seule. Les actions suivantes sont hors périmètre : équiper/déplacer un objet, lancer une fabrication, améliorer un objet, réclamer le Vault, transférer une monnaie, démarrer une clé ou déclencher une action de jeu. Certaines fonctions de mutation existent sans que les docs générées précisent toujours l'exigence de clic matériel; elles restent **RESTRICTED / TO VERIFY** et ne doivent pas être appelées.

Tout changement de cadre protégé, attribut sécurisé, binding ou disposition protégée doit être différé tant que `InCombatLockdown()` est vrai, puis rejoué sur `PLAYER_REGEN_ENABLED`. `C_RestrictedActions.CheckAllowProtectedFunctions` existe, mais ne constitue pas un contournement des règles de sécurité.

### Communications addon

Le protocole doit enregistrer un préfixe avec `C_ChatInfo.RegisterAddonMessagePrefix`, tester les restrictions, traiter la valeur de retour de `SendAddonMessage`, throttler et accepter la perte de messages. Une réponse `AddOnMessageLockdown` est un état normal. Aucun calcul Cortex essentiel ne doit dépendre de la communication dans un donjon, raid, encounter, challenge mode ou match PvP.

## MVP Cortex techniquement fiable

Le MVP recommandé est un **assistant de préparation et de progression hors combat**, entièrement fonctionnel sans communication addon et sans combat log brut :

1. **Profil local et snapshots d'alts** : identité, classe, niveau et équipement du personnage connecté, persistés seulement hors combat et sans valeur secrète.
2. **Tableau de progression** : monnaies/caps, réputation, Renown, quêtes en cours et complétions de quêtes de compte pour une liste d'IDs maintenue.
3. **Great Vault et semaine** : cases, seuils, progression Mythic+/raid/Delves exposée par `C_WeeklyRewards`, plus clé possédée et historique Mythic+.
4. **Conseils d'équipement et d'amélioration** : slots faibles, ilvl, statistiques et high-watermarks; recommandations seulement, jamais d'action.
5. **Collections ciblées** : montures et transmogs d'abord, car leurs APIs sont structurées et account-wide; autres collections ajoutées séparément après audit.
6. **Bilan post-combat expérimental, désactivable** : seulement si `C_DamageMeter.IsDamageMeterAvailable()` est vrai et après levée des restrictions. Ce module ne doit pas bloquer le reste du MVP.

À repousser après le MVP : coaching en combat, replay exhaustif du combat log, synchronisation fiable en instance, crafting automatique, transfert de monnaie, réclamation de récompense, profil complet d'alts hors ligne et historique rétroactif de loot/instances.
